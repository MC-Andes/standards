# Guía de contribución

¡Gracias por contribuir a MC-Andes!

## Flujo

1. Abre un issue (bug/feature/question) o toma uno existente.
2. Crea una rama desde `main`.
3. Implementa el cambio con pruebas/documentación.
4. Abre un Pull Request usando la plantilla.
5. Atiende feedback de revisión.

## Requisitos mínimos

- CI en verde.
- Cambios documentados en README/docs cuando aplique.
- Pruebas para cambios funcionales.

## Estilo

- Commits: Conventional Commits.
- Nombres claros en ramas, archivos y PR.
- Mensajes de PR con contexto técnico y validación.
